# 课程登记

跨集共享的内容状态：有哪些系列、每集讲哪个概念、哪些概念和代码词已经讲过、素材代码从哪里来。单集的细节在 `videos/<id>/`，这里只记跨集要对齐的东西。`node tools/vt.mjs curriculum` 检查这里的文件彼此一致，`vt check` 也会跑这一项。

| 文件 | 内容 | 什么时候改 |
|---|---|---|
| `NN-<系列>.md` | 系列大纲：总表（集的顺序、概念、前置、状态）与每集的计划。文件名前的序号就是系列的顺序 | 立项新的一集、一集的阶段变化、调整计划时 |
| `concepts.json` | 概念表：每个概念的标准叫法、一句话定义、由哪一集引入、依赖哪些概念、不要用的别名 | S1 写大纲时登记新概念；S8 发布后状态随总表 |
| `terms.json` | 代码词汇表：代码里的词或记号、英文、中文、在哪一集第一次完整翻译 | S1 列出本集要翻译的词；S7 审片通过后补登 |
| `sources.json` | 素材源码仓：地址、固定的提交号、许可证 | 换素材仓或升级提交号时（升级后对所有用到它的集重跑 `vt code`、`vt evidence`） |

## 用法

- **S0 立项**：在系列总表里找到这一集，`vt new <id> <标题>` 的 id 与标题照抄总表。
- **S1 大纲**：从系列大纲里这一集的条目出发写 `outline.md`。概念链里的每个概念，要么已在 `concepts.json` 里、由前面的集引入，要么在这一集新登记；前面的集已经讲过的概念，只用一句话回顾，不重讲。
- **叫法**：旁白、字幕和画面文字用 `concepts.json` 的 `name`。`avoid` 里的别名会被 `vt lint` 提醒。
- **代码词的翻译级别**：按系列总表的顺序判断。一个词在前面的集已经完整翻译过，这一集只高亮；否则完整翻译，并把 `terms.json` 里它的 `episode` 改成这一集（总表顺序更靠前的集优先）。制作顺序不影响级别。
- **素材代码**：`script.json` 的 `code.source` 写 `sources.json` 里的名字，文件取自固定提交。

## 格式

`concepts.json`：

```
{"id": "guard-bit", "name": "保护位", "def": "被扔掉的第一位，分量是末位的一半", "episode": "fp32-rne", "deps": ["rounding"], "avoid": []}
```

`terms.json`：

```
{"code": "wire", "en": "wire", "zh": "导线", "episode": "fp32-rne"}
```

`episode` 必须出现在某个系列的总表里；`deps` 里的概念必须由同一集或更靠前的集引入。
