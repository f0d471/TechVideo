## 贯穿全系列的例子

`3F800001 × 3FC00000`，即 (1 + 2⁻²³) × 1.5。第 2 集把这两个数拆开，第 4 集把它们相乘，第 6 集给它们的积舍入（结果 `3FC00002`，已由样片的仿真确认）。第 5 集需要一个积落在 [2, 4) 的例子，另选 `3FC00000 × 3FC00000`（1.5 × 1.5 = 2.25）。每集用到的数都在这一集的 S2 由仿真或计算得到，下面写的只是计划。

## 1 `fp32-float-idea` 小数点放在哪

- 问题：32 个格子，怎样既放得下 0.000123 这样的小数，又放得下 12300000 这样的大数，而且两边算得一样准。
- 概念链：二进制小数（小数点右边第 k 位的分量是 2⁻ᵏ）→ 定宽格子 → 定点数：小数点固定在某一位 → 定点的误差：最小一格固定，数越小相对误差越大，数太大又放不下 → 十进制科学计数法 → 二进制科学计数法 1.xxx × 2ᵉ → 浮点数：有效位数固定，小数点的位置单独记下来 → 相对误差在各个量级上都差不多。
- 类比：十进制科学计数法。严格等价在「有效数字位数固定，指数只决定小数点的位置」。
- 要实跑的数：同一组数（例如 0.001、1、1000）分别用 16.16 定点和 FP32 存进去，再读出来的相对误差。用一个小程序计算，放进 `evidence/`。
- 代码：没有对应的代码，这一集只有原理段。
- 角色色（建议）：阶码陶土，有效位蓝。

## 2 `fp32-fields` 32 个格子怎么分

- 问题：1.5 存进内存，为什么是 `3FC00000`。
- 概念链：符号位 → 阶码 8 位与偏置 127（阶码减 127 才是指数，负的指数也能用无符号数存）→ 规格化形式 1.f → 隐藏位：首位总是 1，不存 → 小数位 23 位 → 值 = (−1)ˢ × 1.f × 2^(阶码 − 127) → 例子：1.5 = 1.1₂ × 2⁰ → `0 01111111 100…0` = `3FC00000`；1 + 2⁻²³ = `3F800001`，末位的分量 2⁻²³。
- 代码：第 39–47 行，拆出符号、阶码、小数位，用 `{1'b1, a_frac}` 补回隐藏位。
- 新的代码词：位切片 `[30:23]`、拼接 `{ , }`、常数写法 `1'b1`、注释 `//`。`wire` 在这一集第一次完整翻译。
- 要实跑的数：两个例子的三个字段，由 testbench 读出拆包后的信号。
- 角色色（建议）：符号绿，阶码陶土，小数位蓝，与第 1 集的阶码颜色一致。

## 3 `fp32-special` 阶码的两端

- 问题：按 1.f × 2^(阶码 − 127) 写不出 0；1 ÷ 0、0 ÷ 0 的结果又该怎么存。
- 概念链：规格化公式写不出 0 → 阶码全 0 留作特殊用途：±0 与非规格数（0.f × 2⁻¹²⁶，越来越小时精度逐位减少）→ 阶码全 1：小数位为 0 是无穷，不为 0 是 NaN → 乘法里的特殊组合：任一输入是 NaN 得 NaN，无穷乘 0 得 NaN，无穷乘非零得无穷 → 这份实现把非规格数输入当作 0（偏离标准，第 7 集讲原因）。
- 代码：第 50–63 行，判定 NaN、无穷、零，以及无穷乘 0 的冲突。
- 新的代码词：`==`、`!=`、`&&`、十六进制常数 `8'hFF`。
- 要实跑的数：`00000000`、`80000000`、`7F800000`、`7FC00000`、最小非规格数 `00000001` 的值 2⁻¹⁴⁹；无穷乘 0 的仿真输出。

## 4 `fp32-mul` 两个浮点数相乘

- 问题：(1 + 2⁻²³) × 1.5 在电路里分几路算。
- 概念链：十进制科学计数法相乘（有效数相乘，指数相加）→ 符号：同号得正、异号得负，就是异或 → 阶码：两个带偏置的阶码相加多出一个 127，要减掉 → 阶码和要用 10 位带符号数：结果可能小于 0 或大于 255，留给第 7 集判断 → 尾数：24 位乘 24 位得 48 位 → 两个 [1, 2) 的数相乘，积落在 [1, 4)，整数部分占两位。
- 代码：第 48 行符号异或，第 65–67 行尾数乘法与带符号的阶码和。
- 新的代码词：`^`、`*`、`$signed`、`10'sd127`、零扩展 `{2'b0, a_exp}`。
- 要实跑的数：例子的符号、阶码和、48 位积（与样片 `evidence/sim.log` 的积核对）。

## 5 `fp32-normalize` 规格化

- 问题：1.5 × 1.5 = 2.25，积的首位跑到了第 47 位，怎么办。
- 概念链：规格化形式回顾 → 积在 [1, 2)：已经规格化，不动 → 积在 [2, 4)：右移一位、阶码加一（十进制对照：22.5 × 10³ = 2.25 × 10⁴）→ 右移时掉出去的最低位不能丢，并进最低位，留给舍入时的粘滞位 → 两个规格化数的积不会小于 1，所以乘法只需要右移，不需要左移。
- 代码：第 116–129 行，`always @(*)` 里的 `if` 与右移，第 124 行把掉出的位并回来。
- 新的代码词：`reg`、`always @(*)`、`if`/`else` 在电路里是二选一的选择器、`>>`、组合块里的 `=`（同形记号表要补一行）。
- 要实跑的数：`3FC00000 × 3FC00000` 的积与右移后的积；一个右移时掉出位为 1 的例子。

## 7 `fp32-boundary` 舍入之后

- 问题：舍入加一后尾数可能变成 10.000…，阶码也可能超出能存的范围。
- 概念链：舍入进位使尾数溢出 → 再右移一位、阶码再加一 → 上溢：阶码 ≥ 255 时结果写成 ±无穷 → 下溢：阶码 ≤ 0，标准要求逐渐下溢成非规格数 → 这份实现直接写成 ±0，叫 FTZ（flush to zero），属于有意偏离标准：先讲标准，再讲这份实现，再讲 GPU 的 FTZ 模式、ARM 的 FZ 位、x86 的 FTZ/DAZ 也这样做 → 代价与收益：丢掉 2⁻¹⁴⁹ 到 2⁻¹²⁶ 之间的数，省掉处理非规格数的电路。
- 代码：第 137–155 行，舍入后的尾数、进位、最终阶码、`ftz_out`、`overflow` 与结果选择。
- 新的代码词：`? :` 选择、`assign`、比较里的 `<=` 与 `>=`（同形记号）、`32'h7FC00000`。
- 要实跑的数：尾数进位的例子、上溢例子、下溢例子的仿真输出，以及同一个下溢例子按标准应得的非规格数。

## 8 `fp32-pipeline` 为什么切成两拍

- 问题：同一套乘法电路，为什么要在中间插一排寄存器。
- 概念链：门电路有延迟 → 寄存器与时钟：时钟沿到来时存进去 → 两个寄存器之间最长的那条路决定时钟能多快（关键路径）→ 在中间切一刀：每拍只走一半的路，时钟可以更快，结果晚一拍出来 → 延迟与吞吐 → 有效信号跟着数据一起往下走。
- 代码：第 69–88 行第一级寄存器，第 111–114 行有效信号，第 157–160 行输出寄存器，第 165–195 行把两级连起来。
- 新的代码词：`always @(posedge clk)`、时钟块里的 `<=`（同形记号）、`module`、端口、例化。
- 要实跑的数：切一刀前后的最高时钟频率，取自综合报告，出处写进 `evidence/`。
