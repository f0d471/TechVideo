# 系列：浮点乘法

素材是 `anchorfp` 仓库里的 FP32 两级流水乘法器 `fp/rtl/fp32_mul_pipe.v`（出处见 `sources.json`）。视频里只讲通用知识，不出现仓库名、文件名和源文件行号。

## 情景

我们要做一个 AI 硬件加速器，这个系列做的是它的 FP32 计算核心里的乘法器。

神经网络的计算几乎都是矩阵乘，矩阵乘拆开就是大量的「先乘再累加」。加速器要在一块芯片上同时放很多个乘法器，每个时钟周期都出结果，所以每个乘法器都要小、要快。系列里的每个设计取舍都放回这个情景里解释：

- 为什么用浮点：神经网络里的数有的很大、有的很小，定点数放不下这么宽的范围。
- 为什么 FTZ：非规格数在 AI 计算里极少出现，处理它们的电路却又大又慢，所以直接当成 0。
- 为什么就近舍入到偶数：成千上万次累加，截断的误差会朝一个方向越积越多。
- 为什么切成两拍：每拍都要出一个结果，一整条乘法电路太长，时钟快不起来。

情景是虚构的通用情景，不指向任何具体项目；具体实现只作素材，画面上不出现。

## 贯穿全系列的例子

`3F800001 × 3FC00000`，即 (1 + 2⁻²³) × 1.5。第 1 集把这两个数拆开，第 2 集把它们相乘，第 4 集给它们的积舍入（结果 `3FC00002`，已由第 4 集的仿真确认）。第 3 集需要一个积落在 [2, 4) 的例子，另选 `3FC00000 × 3FC00000`（1.5 × 1.5 = 2.25）。每集用到的数都在这一集的 S2 由仿真、计算或文档得到，下面写的只是计划。

## 1 `fp32-format` IEEE 754 与 FTZ

- 情景里的需求：加速器里的数范围很宽，要选一种数的格式；格式里有一类很小的数，处理起来很贵。
- 问题：一个小数怎样放进 32 位，而且大数小数都算得一样准；标准里那些特别小的数，加速器要不要老老实实处理。
- 概念链，分四部分：
  - 思路：二进制小数（小数点右边第 k 位的分量是 2⁻ᵏ）→ 定点数：小数点固定在某一位 → 定点的误差：最小一格固定，数越小相对误差越大，数太大又放不下 → 科学计数法 → 浮点数：有效位数固定，小数点的位置单独记下来，各个量级上的相对误差差不多。
  - 字段：符号位 → 阶码 8 位与偏置 127 → 规格化形式 1.f 与隐藏位 → 小数位 23 位 → 值 = (−1)ˢ × 1.f × 2^(阶码 − 127) → 例子 `3FC00000` = 1.5、`3F800001` = 1 + 2⁻²³，末位的分量 2⁻²³。
  - 特殊值：阶码全 0 留给 ±0 与非规格数（0.f × 2⁻¹²⁶）；阶码全 1 留给无穷与 NaN。
  - FTZ：标准要求比最小规格化数还小的数写成非规格数，精度逐位减少（逐渐下溢）→ 加速器的选择：非规格数一律当 0，输入当 0、结果写成 0，叫 FTZ，属于有意偏离标准 → 理由放回情景：AI 计算里几乎用不到这么小的数，省下的电路可以多放乘法器 → 业界同样的做法：GPU 的 FTZ 模式、ARM 的 FZ 位、x86 的 FTZ 与 DAZ（出处类型为文档，S2 查原文）。
- 类比：十进制科学计数法。严格等价在「有效数字位数固定，指数只决定小数点的位置」。
- 代码：两段，先后用两个面板出现。第 39–47 行拆出符号、阶码、小数位，并用 `{1'b1, a_frac}` 补回隐藏位；第 51–56 行判定 NaN、无穷和零，其中第 55 行把「阶码全 0」都当成 0，就是输入端的 FTZ。第一段 9 行，正好是一个面板的上限。
- 新的代码词：位切片 `[30:23]`、拼接 `{ , }`、常数 `1'b1` 与 `8'hFF`、`==`、`!=`、`&&`、注释 `//`。`wire` 在这一集第一次完整翻译。
- 要实跑的数：同一组数（例如 0.001、1、1000）用 16.16 定点和 FP32 存进去再读出来的相对误差（计算）；两个例子的三个字段（仿真）；`00000000`、`80000000`、`7F800000`、`7FC00000` 与最小非规格数 `00000001` 的值 2⁻¹⁴⁹（计算）；一个非规格数输入被当成 0 的仿真输出。
- 片长预计 8–12 分钟，是这个系列最长的一集。
- 角色色（建议）：阶码陶土，小数位蓝，符号绿。

## 2 `fp32-mul` 两个浮点数相乘

- 情景里的需求：矩阵乘的每一步都是一次乘法再加一次，乘法器是计算核心的一半。
- 问题：(1 + 2⁻²³) × 1.5 在电路里分几路算。
- 概念链：十进制科学计数法相乘（有效数相乘，指数相加）→ 符号：同号得正、异号得负，就是异或 → 阶码：两个带偏置的阶码相加多出一个 127，要减掉 → 阶码和要用 10 位带符号数：结果可能小于 0 或大于 255，留给第 5 集判断 → 尾数：24 位乘 24 位得 48 位 → 两个 [1, 2) 的数相乘，积落在 [1, 4)，整数部分占两位 → 任一输入是 NaN 得 NaN，无穷乘 0 得 NaN。
- 代码：三段，先后用面板出现。第 48 行符号异或，第 59–60 行无穷乘 0 的冲突，第 65–67 行尾数乘法与带符号的阶码和。
- 新的代码词：`^`、`*`、`$signed`、`10'sd127`、零扩展 `{2'b0, a_exp}`。
- 要实跑的数：例子的符号、阶码和、48 位积（与第 4 集 `evidence/sim.log` 的积核对）；无穷乘 0 的仿真输出。

## 3 `fp32-normalize` 规格化

- 情景里的需求：乘出来的积要写回同一种格式，下一次乘加才能接着用。
- 问题：1.5 × 1.5 = 2.25，积的首位跑到了第 47 位，怎么办。
- 概念链：规格化形式回顾 → 积在 [1, 2)：已经规格化，不动 → 积在 [2, 4)：右移一位、阶码加一（十进制对照：22.5 × 10³ = 2.25 × 10⁴）→ 右移时掉出去的最低位不能丢，并进最低位，留给舍入时的粘滞位 → 两个规格化数的积不会小于 1，所以乘法只需要右移，不需要左移。
- 代码：第 116–129 行，`always @(*)` 里的 `if` 与右移，第 124 行把掉出的位并回来。
- 新的代码词：`reg`、`always @(*)`、`if`/`else` 在电路里是二选一的选择器、`>>`、组合块里的 `=`（同形记号表要补一行）。
- 要实跑的数：`3FC00000 × 3FC00000` 的积与右移后的积；一个右移时掉出位为 1 的例子。

## 5 `fp32-boundary` 舍入之后

- 情景里的需求：训练里的梯度可能非常小，也可能在某一步突然很大，结果必须有确定的写法。
- 问题：舍入加一后尾数可能变成 10.000…，阶码也可能超出能存的范围。
- 概念链：舍入进位使尾数溢出 → 再右移一位、阶码再加一 → 上溢：阶码 ≥ 255 时结果写成 ±无穷 → 下溢：阶码 ≤ 0，按第 1 集的 FTZ 写成 ±0（标准在这里会写成非规格数）。
- 代码：第 137–155 行，舍入后的尾数、进位、最终阶码、`ftz_out`、`overflow` 与结果选择。
- 新的代码词：`? :` 选择、`assign`、比较里的 `<=` 与 `>=`（同形记号）、`32'h7FC00000`。
- 要实跑的数：尾数进位的例子、上溢例子、下溢例子的仿真输出，以及同一个下溢例子按标准应得的非规格数。

## 6 `fp32-pipeline` 为什么切成两拍

- 情景里的需求：加速器每个时钟周期都要从每个乘法器拿到一个结果。
- 问题：同一套乘法电路，为什么要在中间插一排寄存器。
- 概念链：门电路有延迟 → 寄存器与时钟：时钟沿到来时存进去 → 两个寄存器之间最长的那条路决定时钟能多快（关键路径）→ 在中间切一刀：每拍只走一半的路，时钟可以更快，结果晚一拍出来 → 延迟与吞吐 → 有效信号跟着数据一起往下走。
- 代码：第 69–88 行第一级寄存器，第 111–114 行有效信号，第 157–160 行输出寄存器，第 165–195 行把两级连起来。
- 新的代码词：`always @(posedge clk)`、时钟块里的 `<=`（同形记号）、`module`、端口、例化。
- 要实跑的数：切一刀前后的最高时钟频率，取自综合报告，出处写进 `evidence/`。
