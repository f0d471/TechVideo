# 代码课规范

代码段接在原理段之后，任务是把原理段最后得出的规则对到真实代码上。观众里有不写代码的人，也有写软件、不关心 Verilog 的人，所以代码段讲的是结构：这段描述画出来是什么部件、怎么连，和原理段的哪条结论对应。语法只讲到能看懂结构为止。

## 一、硬件描述语言的定位

Verilog 这类硬件描述语言，写的不是「先做什么、后做什么」的步骤，而是「有哪些部件、它们怎么连」。定位成建模：像在 MATLAB 的 Simulink 里搭框图，放几个方块，再用线连起来。两者严格等价的一点是：描述的部件同时存在，信号一变，下游立刻跟着变，和写的先后顺序无关（旧版舍入画面把四行调换顺序，电路不变）。代码段第一次出现时用一两句话交代这个定位，之后一直按「画结构」来讲；现行样片 `fp32-format` 的代码段按此规则先快讲拆字段，再细讲零判断。

代码段的读法按重要程度分两档：

| 档 | 什么样的行 | 怎么讲 |
|---|---|---|
| 快讲 | 连线、切位、拼接这类一眼能对上结构的行；a、b 两份相同的行 | 几行合成一两句：「wire 是连线，这几行把 32 根线分成三束，名字依次是符号、阶码、小数位，b 也一样」。信号名一次性摆出，不逐个翻译 |
| 细讲 | 和原理段结论直接相关、或者容易读错的行（现行样片只查阶码的零判断就是输入端的 FTZ；旧版舍入的舍入判断） | 逐项对到电路，用例子送进去看输出 |

- 注释（`//` 后面的文字）不讲，也不在画面上标出来。
- C 这类顺序执行的语言，结构层改成「这一行执行后，哪个变量变成了什么值」。

## 二、翻译分级

名字和记号只讲到结构需要的程度。一个词第一次出现时用一句话说清它在结构里是什么（`wire` 是连线，`==` 是比较器），以后不再处理。跨集的「第一次」按系列总表的顺序算，记在 `curriculum/terms.json`：总表里更靠前的集已经讲过的词，这一集不再讲；否则这一集讲一次，并把词汇表里这个词的 `episode` 改成这一集。S1 写大纲时列出本集要讲的词。

- 信号名（`a_sign`、`a_exp`、`a_frac`、`a_mant`）用一张名字表一次摆出：名字 → 中文，和原理段的角色色一致，一个 beat 说完。英文全称只在名字来由不明显时补一句。
- 中文用 `terms.json` 的 `zh`，可以缩短，不换说法。
- 结构相同、只换了输入的几行（a 与 b 各一份）：合成一句话带过，画面一次长出整组。反例（fp32-format 首稿）：b 的每一行各占一个 beat。
- 节奏：代码段平均每行代码不超过 1.5 个 beat（`tools/limits.json` 的 `codeBeatsPerLine`，`vt lint` 提醒）。反例（fp32-format 第二稿）：15 行代码 39 个 beat，`wire`、方括号的两种用法、注释、常数的每一部分各占一个 beat，p88 一整页只讲 `[7:0]` 是声明宽度。

## 三、同形记号按位置翻译

同一个记号出现在不同位置，含义可能完全不同，翻译时看位置，不看字面。已遇到的记号：

| 记号 | 位置 | 译成 | 素材里的例子 |
|---|---|---|---|
| `<=` | 表达式里（C 与 Verilog 相同） | 小于等于，比较 | `fp32_mul_pipe.v` 第 141 行 `ftz_out = (exp_final_s <= 10'sd0)` |
| `<=` | Verilog 时钟块 `always @(posedge clk)` 里，语句开头 | 时钟沿到来时存进寄存器 | 同文件第 159 行 `p <= spec_sel_r ? …` |
| `=` | `wire x = …` 或 `assign` | 连线，右边一变左边立刻跟着变 | 同文件第 132 行 |
| `=` | Verilog 的组合块 `always @(*)` 里，语句开头 | 块内赋值；两分支都赋值时，输出由条件选择的组合路径决定 | 同文件第 122–127 行 |
| `=` | C 语句 | 赋值，把右边的值复制进左边的格子 | — |
| `|` | 写在最前 | 归约或：一排线全部「或」在一起 | 同文件第 133 行 `|prod_n[21:0]` |
| `|` | 写在两个信号中间 | 或 | 同文件第 135 行 `sticky_bit | mant_lsb` |
| `[高:低]` | `wire` 后、名字前 | 声明导线束的宽度，包含两端 | 同文件第 40 行 `wire [7:0] a_exp`，共 8 位 |
| `[高:低]` | 来源名字后 | 从来源中取连续的一组位，包含两端 | 同文件第 40 行 `a[30:23]`，取出 8 位 |

每集遇到新的同形记号，补进这张表。

## 四、引用

- 视频里的代码只来自 `vt code` 的抽取结果 `build/code.json`：文件取自 `curriculum/sources.json` 固定的提交，逐字显示，保留原缩进与注释。不改名、不删参数、不重排。
- 代码片段当作一段独立的代码呈现。面板右上角只标语言名（`code.json` 的 `lang`，例如 Verilog）；不显示文件名、仓库名和源文件行号，也不写「已折叠」「后续省略」这类说明。观众不认识素材项目，这些信息对他们没有意义。
- 旁白和画面文字用片段内的相对位置指代代码：「第一行」「下一行」「最后一行」。
- 一集可以引用几段代码，写在 `script.json` 的 `code` 数组里，一段一项，每段有自己的名字，是连续的几行，最多 9 行（`tools/limits.json` 的 `codeLines`，`vt code` 检查）。要讲的几行不相邻时分成几段，每段一个面板，先后出现：前一块淡出，后一块描框出现。不在一段代码中间插省略标记。
- 演示「调换顺序」这类假设时，演示结束恢复原顺序。
- `code.json` 记录素材仓、提交号和文件的 sha256，只作出处记录。升级素材仓的提交号后重抽，如果提示文件改过，核对画面里引用的行与记号。

## 五、版面

核心公式条常驻画面顶部（`visual.md` 第四节），代码面板放在它下面。短片段可照现行样片放在左侧，右侧给结构图；片段较宽时可让面板占满内容区上方，结构图放在下方。名字表（信号名 → 中文，角色色）放在剩余空间里，结构图始终是主角。讲到哪几行，那几行加底色，要细讲的记号加手绘下划线，颜色与原理段里同一概念的角色色一致。逐词翻译表（`TransTable`）只在名字来由确实需要英文全称时用。

## 六、电路图的画法

- 代码段的每一页都有电路：用 `src/components/Gates.tsx` 的门、运算单元、导线与信号值画，外面套 `Circuit`。出现代码面板而没有电路的页，`vt layout` 报错。方框加箭头的框图不算电路：一个运算画成对应的门或运算单元（异或门、或门、选择器、加法器、乘法器），信号名写在导线上。反例（fp32-mul、fp32-normalize 首稿）：代码段全部是写着信号名的方框，用箭头连起来。
- 电路图占满预留的结构区（可在面板右侧或下方，内容到 y=900），门和信号框用 `src/components/Gates.tsx` 的原尺寸，不用 `scale()` 缩小；元件多到放不下时，只画当前讲的那一组，讲过的组淡出或收成一行标志。
- 结构图里的每个部件、每根线都由同一组坐标常量算出位置，箭头和导线的端点落在部件的边上（`visual.md` 第四节「对齐」）。
- 信号从左往右流：信号源在左，门在中间，输出在右。
- 一行代码对应的元件，在讲到这一行时才出现。
- 多位总线画成一根粗线，加斜杠与位数标注。
- 最后用原理段的例子把具体的 0 和 1 送进电路，输出要与原理段手算的结果一致。
