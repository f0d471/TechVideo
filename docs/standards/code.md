# 代码课规范

代码段接在原理段之后，任务是把原理段最后得出的规则对到真实代码上。观众默认不会写代码，所以每一行都从词、句型、电路三个角度讲，最后讲几行合起来构成什么。

## 一、四层读法

| 层 | 讲什么 | 样片里的例子 |
|---|---|---|
| 逐词翻译 | 代码 → 英文全称 → 中文 | `prod_n` → product, normalized → 规格化后的积 |
| 语法形状 | 一行的骨架，每个位置叫什么 | `wire 名字 = 来源 ;`：导线、名字、等号、来源、分号 |
| 代码到电路 | 这一行在电路里对应什么元件（Verilog 必讲） | 第一行对应一根从第 22 位接出来的线 |
| 结构 | 几行合起来构成什么 | 四行合起来是一个三输入的判定电路；四行调换顺序，电路不变 |

Verilog 描述的是同时存在的连线和寄存器，读的时候不按从上到下执行的顺序理解。C 这类顺序执行的语言，第三层改成「这一行执行后，哪个变量变成了什么值」。

## 二、翻译分级

一个词第一次出现时完整翻译，第二次只高亮，第三次起不再处理。跨集的「第一次」按系列总表的顺序算，记在 `curriculum/terms.json`：总表里更靠前的集已经完整翻译过的词，这一集按第二次出现处理；否则这一集完整翻译，并把词汇表里这个词的 `episode` 改成这一集。S1 写大纲时列出本集要翻译的词和各自的级别。

- 翻译表里的中文用 `terms.json` 的 `zh`，可以缩短，不换说法。反例（fp32-format 首稿）：`=` 在词汇表里是「连线」，画面上写成「连续连接」。
- 结构相同、只换了输入的几行（a 与 b 各一份）：第一份逐行讲，第二份合成一个 beat 一句话带过（「后三行对 b 做同样的事」），画面一次长出整组。反例（fp32-format 首稿）：b 的每一行各占一个 beat（「第 4 行，同样取出 b 的符号位」「第 5 行，接出 b 的 8 位阶码」……），代码段 45 个 beat 里有 7 个是这种重复。
- 一个 beat 讲一个记号，但只讲这一集用得上的那一层。代码段的 beat 数与样片同一量级：样片 4 行代码 14 个 beat；行数多时，先删重复的行和不影响理解的记号，不要逐个记号平推。

## 三、同形记号按位置翻译

同一个记号出现在不同位置，含义可能完全不同，翻译时看位置，不看字面。已遇到的记号：

| 记号 | 位置 | 译成 | 素材里的例子 |
|---|---|---|---|
| `<=` | 表达式里（C 与 Verilog 相同） | 小于等于，比较 | `fp32_mul_pipe.v` 第 141 行 `ftz_out = (exp_final_s <= 10'sd0)` |
| `<=` | Verilog 时钟块 `always @(posedge clk)` 里，语句开头 | 时钟沿到来时存进寄存器 | 同文件第 159 行 `p <= spec_sel_r ? …` |
| `=` | `wire x = …` 或 `assign` | 连线，右边一变左边立刻跟着变 | 同文件第 132 行 |
| `=` | C 语句 | 赋值，把右边的值复制进左边的格子 | — |
| `|` | 写在最前 | 归约或：一排线全部「或」在一起 | 同文件第 133 行 `|prod_n[21:0]` |
| `|` | 写在两个信号中间 | 或 | 同文件第 135 行 `sticky_bit | mant_lsb` |
| `[高:低]` | `wire` 后、名字前 | 声明导线束的宽度，包含两端 | 同文件第 40 行 `wire [7:0] a_exp`，共 8 位 |
| `[高:低]` | 来源名字后 | 从来源中取连续的一组位，包含两端 | 同文件第 40 行 `a[30:23]`，取出 8 位 |

每集遇到新的同形记号，补进这张表。

## 四、引用

- 视频里的代码只来自 `vt code` 的抽取结果 `build/code.json`：文件取自 `curriculum/sources.json` 固定的提交，逐字显示，保留原缩进与注释。不改名、不删参数、不重排。
- 代码片段当作一段独立的代码呈现。面板右上角只标语言名（`code.json` 的 `lang`，例如 Verilog）；不显示文件名、仓库名和源文件行号，也不写「已折叠」「后续省略」这类说明。观众不认识素材项目，这些信息对他们没有意义。
- 旁白和画面文字用片段内的相对位置指代代码：「第一行」「下一行」「最后一行」。
- 一集可以引用几段代码，写在 `script.json` 的 `code` 数组里，一段一项，每段有自己的名字，是连续的几行，最多 9 行（`tools/limits.json` 的 `codeLines`，`vt code` 检查）。要讲的几行不相邻时分成几段，每段一个面板，先后出现：前一块淡出，后一块描框出现。不在一段代码中间插省略标记。
- 演示「调换顺序」这类假设时，演示结束恢复原顺序。
- `code.json` 记录素材仓、提交号和文件的 sha256，只作出处记录。升级素材仓的提交号后重抽，如果提示文件改过，核对画面里引用的行与记号。

## 五、版面

代码面板占画面上方全宽；左下是逐词翻译表（`TransTable`）和语法形状或同形记号的对照；右下是随代码逐行长出来的电路（`Gates` 里的门、导线、信号值）。讲到哪一行，那一行加底色，被翻译的记号加手绘下划线，颜色与原理段里同一概念的角色色一致。

## 六、电路图的画法

- 电路图占满右下区域（x 960–1824，y 580–900），门和信号框用 `src/components/Gates.tsx` 的原尺寸，不用 `scale()` 缩小；元件多到放不下时，只画当前讲的那一组，讲过的组淡出或收成一行标志。
- 信号从左往右流：信号源在左，门在中间，输出在右。
- 一行代码对应的元件，在讲到这一行时才出现。
- 多位总线画成一根粗线，加斜杠与位数标注。
- 最后用原理段的例子把具体的 0 和 1 送进电路，输出要与原理段手算的结果一致。
