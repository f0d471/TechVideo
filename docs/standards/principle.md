# 原理课规范

原理段的任务，是把这一集的问题从观众已有的知识一路推到一条可以写成代码的规则。现行样片是已发布的 `videos/fp32-format`；`fp32-rne` 已按同一套规范重做并审片通过。下文的 `fp32-rne` 例子说明局部推导手法，整集结构以条文和现行样片为准。

## 一、观众起点

默认起点：高中数学，会任意进制之间的转换，再加上系列总表里前置集讲过的概念（`curriculum/concepts.json` 里由更靠前的集引入的概念）。起点以下的内容不讲；前置集讲过的概念只用一句话回顾；其余每个新概念都要拆。不重要的概念用一句话带过，不展开成段落。某一集需要不同的起点时，写在它的 `outline.md` 里。

观众里软件和硬件的人都有。写模型、写推理框架的人不懂也不关心 Verilog，做芯片的人不熟悉模型。所以模型一侧的词（推理、参数、乘加）和电路一侧的词（连线、比较器、逻辑门）第一次出现时都用一句话说清它是什么，不假定任何一边的背景。

## 二、概念依赖链

写脚本前先在 `outline.md` 里排出概念链：按出现顺序列出每个新概念，并写明它依赖哪些前面的概念。一个概念出现之前，它依赖的概念必须已经在画面上出现过。

舍入画面的局部概念链：格子有限 → 相邻两格 → 舍入是二选一 → 截断 → 就近 → 平局 → 十进制对照 → 往偶数靠 → 保护位 → 粘滞位 → 末位 → 一条规则。正负数的论断边界见该集 `outline.md`。

## 三、先给实物，再给名字

新概念第一次出现时，先在画面上指出它是哪个东西，再命名。舍入画面里保护位先以「被扔掉的第一位」出现，粘滞位先是「后面 22 位里有没有 1」。小节开头点题（第三节之二）可以直接说出这一小节要讲的名字，定义仍随实物出现。

## 三之二、小节：停顿、提示、点题

视频要有结构感。每个新概念是一个小节，小节之间有明显的换段：

- 停顿：上一小节最后一句加 0.8–1.2 秒 `hold`，让观众知道一段讲完了。
- 提示：画面左上角的小节标签换成新小节的名字（`script.json` 里小节第一句的 `section` 字段），标签出现时有一次描线；几个小节组成的一部分开始时，先出一张无旁白的部分卡（约 1.5 秒）。
- 点题：小节的第一句话说清接下来十几秒讲什么，并且从上一小节留下的问题或情景里的需求接过来，让观众自己看出为什么需要它。样式：「照这个公式，1.F 最小也是 1，零根本写不出来，所以标准专门留了几组编码」「指数会是负数，可这 8 位里没有地方放负号」。
- 不把衔接说破：不说「第一性原理」「为什么要学」「接下来我们学习」这类字样，衔接靠需求和问题本身。`vt lint` 对这些字样报错，对小节前没有停顿的给提醒。

## 四、静音可懂

把旁白关掉，画面自己要能讲通。每个结论都要有画面上的对应物：截断是三个点全部拐向左边，偶数规则是两条数轴上的和，一个是 10，一个是 8。

## 五、一个 beat 只推进一个状态

判定树一句话长一个分支，公式一句话出现一层。一个画面里同时有三处在变，观众只能跟上一处。

## 六、类比必须严格等价

类比要在讲解的那一点上与原概念完全等价，并在 `outline.md` 里写明等价在哪。舍入画面用十进制的 0.5、1.5、2.5、3.5 类比二进制的平局，两者等价在「被扔掉的部分恰好等于末位的一半」。只在表面上相似的类比不用。

## 七、数字全部有出处

画面上出现的每个数字、位串、结果、计数，都登记在 `outline.md` 的数字清单里，并写明出处类型：

| 出处类型 | 什么时候用 | 登记什么 |
|---|---|---|
| 仿真 | 电路的输入输出、中间信号 | `evidence/` 里的实验文件与原始日志 |
| 实测 | 时序、资源、速度这类要跑工具才得到的数 | `evidence/` 里的命令、工具版本与原始输出 |
| 文档 | 标准的规定、引用的报告 | 文档名与章节，摘录放进 `evidence/` |
| 算术 | 手算就能核对的十进制例子 | 写出算式，例如 0.5+1.5+2.5+3.5=8 |

舍入画面的例子 `3F800001 × 3FC00000` 的 48 位积、保护位、粘滞位、末位和结果 `3FC00002` 都来自对素材 RTL 的仿真；十进制平局的例子是算术。

## 八、偏离标准的做法当作概念讲

素材里有意偏离标准的做法（例如非规格数冲零 FTZ），把偏离本身当成一个概念：先讲标准怎么规定，再讲情景里的加速器为什么这样做（放回系列的情景里解释，见第十一节），以及业界哪些硬件也这样做。主语是情景里的加速器和业界的做法，不是「这个乘法器」：素材只是参照，观众不认识它。

- 理由用系列大纲里写好的那条（FTZ：AI 计算里几乎用不到这么小的数，处理它们的电路又大又慢，省下来可以多放乘法器）。
- 代价讲一次，用这一集已有的例子讲清丢了什么，然后说情景为什么接受它。不把结论改成「看情况」「要验证」，不为了显得严谨再加反例和免责句。
- 业界做法举与情景同类的硬件（GPU、x86、Arm 的 FZ 位），一种一句话；编译开关、寄存器全名、文档章节号不上画面。
- 反例（fp32-format 首稿）：FTZ 的理由写成「如果目标模型能接受这种损失」「是否合算，要用目标模型验证」，又加了两句「小输入影响未必小」的反例，这一部分的结论从「加速器选择冲零」变成了「看情况」。

## 九、从原理到代码的桥

原理段的最后一条规则，就是代码段要实现的规格。代码段开头回到这条规则，让观众知道接下来的每一行在实现规则的哪一部分。

## 十、一集的范围

- 一集回答一个问题，讲一个概念，或者几个前后相接的小概念。几个概念连贯、单独成集又都撑不满时，在总表里合成一集（例：浮点数的思路、单精度的字段、特殊值和 FTZ 都在回答「一个小数怎样放进 32 位」，合成一集）；一个概念太大时拆成几集。
- 合成的一集按概念分成几部分，每部分仍按本规范讲：先给实物再给名字，一个 beat 只推进一个状态。
- 片长随内容走，落在 `tools/limits.json` 的区间内（3–12 分钟），`vt tts` 会检查。
- 一集的骨架：片头（标题与这一集要回答的问题）→ 从情景需求和前置概念引出问题 → 原理段 → 桥 → 代码段 → 用开头的例子验证 → 一句话交代结果交给下一步。现行样片从推理芯片的乘加需求引出数值格式，结尾把两个输入交给下一集的乘法；新版舍入从反复乘加中的误差引出舍入，结尾把尾数进位与范围问题交给下一集。
- 系列的第一集在片头之后先讲情景和切入点：情景里的需求有多大（带出处的数）→ 芯片上有哪几种数的格式、各自的代价 → 为什么拿这一种举例 → 这一集要读懂的核心公式。观众先知道学这个有什么用，再进原理段。以后各集开头一句话回顾情景即可。
- 核心公式常驻：一集有一条贯穿的核心公式或核心结构（第 1 集是 FP32 的位域图和 (−1)^S × 1.F × 2^(E−127)），从开场起常驻画面顶部，讲到哪一项哪一项亮起，公式里的字母用角色色（`visual.md` 第四节）。
- 开场：前三句旁白让观众知道这一集要解决什么。现行样片前三句是「推理需要大量乘加 → 数怎样存决定运算代价 → FP32 怎样把小数装进 32 位」。片头卡上的问题只停两秒，不能代替旁白。合成的一集，每一部分的第一句交代这一部分回答问题的哪一半。反例（fp32-format 首稿）：前三句是「给加速器做乘法器 → 每个输入用 32 位 → 这两串位稍后会还原成输入」，没有说出「一个小数怎样放进 32 位」，FTZ 那一半问题直到第 68 页才出现。
- 代码段可选。概念在素材里没有直接对应的代码（例如「浮点数为什么用阶码」），这一集只有原理段，不为了凑代码段去找代码。

## 十一、情景

- 一个系列可以设一个贯穿的情景，写在系列大纲开头。「FP32 是怎么计算的」系列的情景是 AI 模型推理和为它设计的加速器芯片，软件和硬件两边的人都能代入。
- 每集在系列大纲里写一句「情景里的需求」，片头之后的开场从这个需求引出这一集的问题。
- 取舍用情景的需求解释：FTZ 是因为 AI 计算里几乎用不到非规格数、省下的电路可以多放乘法器；流水线是因为每拍都要出一个结果。
- 知识点全部以情景为背景，项目只是参照。旁白说「推理芯片」「AI 加速器」「很多 AI 芯片」，不说「这个乘法器」「这个实现」；素材算出来的结果说成「按冲零的做法，结果是 0」。`vt lint` 对「这个乘法器」报错。反例（fp32-format 第二稿）：p72 画面上一行「这个乘法器 → −0」，观众不知道是哪个乘法器，又回到了讲项目。
- 情景是虚构的通用情景，不指向具体项目，素材仓名与文件名照样不出现。

## 十三、引用

情景里的需求、业界的选择、标准的来历，用经典论文、标准文档和厂商文档作依据，引用本身也是画面内容的一部分，给视频加分量。

- 什么时候引：一个会被人问「凭什么这么说」的论断（每个词要几十亿次乘加、非规格数会慢几十倍、AI 芯片冲零），和一段值得讲的来历（逐渐下溢当年的争论）。
- 怎么上画面：引用卡写作者、年份、出处（会议或期刊），加一句这篇文献说了什么；有数据的，把数据按原文重画成图表，不贴截图。
- 图片只用许可允许的：公有领域、CC0、CC BY，或以 CC BY 发布的论文页面。图片旁写作者与许可（许可要求的署名）。CC BY-SA、版权保留的图片与论文截图不用。图片与许可登记在这一集的 `evidence/references.md`，文件放在 `videos/<id>/assets/`。
- 引用卡里的数字同样登记进数字清单，出处类型为「文档」。
- 一集的引用控制在十处以内，每处一两个 beat，不喧宾夺主。

## 十二、例子怎么选

例子的任务是让结论一眼可见。选完以后自问：只看例子，观众得出的结论和旁白说的一致吗。

- 例子直接支持这一步要说的结论，也支持情景里的理由。比较两种做法时，例子要覆盖情景关心的那个维度。「为什么用浮点」的理由是范围宽（系列大纲：定点数放不下这么宽的范围），例子里就要有定点数存成 0 或放不下的数。
- 需要旁白补一句「这一行反而……」「这个例子里……」来解释的例子，换掉。
- 不用刻意构造、结果恰好相等的例子，除非构造方式本身就是要讲的内容。观众会把巧合当成规律。
- 用到的术语都已经讲过。例子的说明里出现还没讲的概念（例如在讲字段之前用「普通数的范围内」），属于先用后讲。
- 反例（fp32-format 首稿）：定点与浮点的比较表取 0.001、1.024、1048.576，后两个是前一个乘 2¹⁰、2²⁰，浮点的相对误差被构造成三行完全相同；第三行定点反而更准，只好加一句「这一行的定点反倒更精细」；而「定点放不下」这个情景里的理由，表里一行也没有。
