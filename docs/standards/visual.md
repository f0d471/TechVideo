# 视觉规范

浅色暖底，线条手绘，数字和代码用等宽字体。视觉效果的上限是手绘，不用渐变、发光、三维透视、粒子、胶片颗粒这类效果。配色与字体都定义在 `src/core/theme.ts`，画面代码只引用 `C` 和 `F`，不写颜色字面量。颜色字面量、渐变滤镜阴影、三维变换、按真实时间或随机数变化的写法、画面文字里的素材项目名和出处说明，由 `vt check`（`tools/lint_scenes.mjs`）报错；越档字号、`scale()` 缩放、Unicode 上标、概念别名、超长的代码行给提醒。

## 一、配色与角色

| 名称 | 变量 | 色值 | 用途 |
|---|---|---|---|
| 底色 | `C.ground` | `#F0EEE6` | 画面背景 |
| 纸面 | `C.paper` | `#FAF9F5` | 卡片、代码面板、节点框 |
| 墨 | `C.ink` | `#1F1E1C` | 正文、主线条 |
| 次级 | `C.ink2` / `C.muted` / `C.faint` | `#4A4843` / `#7A766D` / `#B7B2A6` | 说明文字、次要线条、淡出的元素 |
| 陶土 | `C.clay`，文字用 `C.clayInk` | `#D97757` / `#B5532F` | 角色色 1 |
| 蓝 | `C.blue`，文字用 `C.blueInk` | `#5B87B4` / `#3F6B97` | 角色色 2 |
| 绿 | `C.green`，文字用 `C.greenInk` | `#6F8A4E` / `#566E39` | 角色色 3 |

- 角色色给这一集里最重要的三个概念，并在整集（原理段和代码段）保持不变，观众靠颜色把公式里的记号和代码里的名字对上。样片里保护位 G 是陶土，粘滞位 S 是蓝，末位 L 是绿。
- 每集开工时在 `outline.md` 里写下角色色分配。角色之外的元素一律用中性色。
- 文字用对应的 `Ink` 深色版本，保证在浅底上可读；线条和填充用浅色版本，淡色填充用 `Tint`。

## 二、字体

- 中文：霞鹜文楷（`F.text`）。数字、位值、代码、英文标识符：JetBrains Mono（`F.mono`）。两者都是 OFL 许可。
- 等宽字体一律关闭连字（`fontVariantLigatures: 'none'`），否则 `<=` 会画成 ≤，`//` 字距会变。`Txt` 的 `mono` 属性已处理。
- 字号分四档：小标注 17–22，正文与概念卡 24–34（代码 25），强调 36–52，片头标题 132；字幕 40。越出这几档的字号 `vt check` 会提醒。字号指画在画面上的实际大小，外面套 `scale()` 缩小的也算在内，`vt check` 对 `scale()` 给提醒。
- 指数不用 Unicode 上标字符（`2⁻¹²⁶`）：等宽字体只有 ¹²³ 几个字形，其余回退到别的字体，同一个指数里大小、间距不一（fp32-format 首稿 p44 的 `2^(E−127)`）。底数与指数分成两段文字，指数用小一档的字号、上移约 0.4 个字高写在右上；`vt check` 对上标字符给提醒。字幕用霞鹜文楷，上标字符在字幕里显示正常，可以用。

## 三、手绘

- 线、框、椭圆、箭头都用 `src/core/rough.tsx` 的 `RLine`、`RRect`、`REllipse`、`RArrow`、`RPath`。随机种子由几何参数算出，同一图元每一帧都长得一样，不会抖。
- 抖动程度 `roughness` 取 0.5–0.9：导线和代码下划线 0.5–0.6，框与箭头 0.7–0.9。
- 出现方式用描线（`draw` 从 0 到 1），历时 12–26 帧；淡入淡出 10–16 帧。
- 位值、数字、代码不手绘，一律用等宽字体排版。

## 四、版面

- 画面 1920×1080，30 fps。左右留白 96 像素。
- 左上角 y=86 是段落标签（「原理 · 舍入」「代码 · 舍入」）。
- 左下角 (96, 1040) 是页码，由 `VideoShell` 画：有旁白的 beat 按顺序从 1 编号，与审阅表的页码一致，审片时用它定位；片头这类无旁白的 beat 不显示。
- 底部 160 像素留给字幕和页码，其他元素不进入 y > 920 的区域。
- 原理段常用布局：上方放贯穿全集的主体（样片的 48 位积，y≈200），中部放当前讲解的推导（y 440–900）；讲中部时主体降低到 30% 不透明度，讲回主体时恢复。
- 代码段布局见 `docs/standards/code.md` 第五节。
- 疏密：当前讲的东西是画面上最大的元素。一个公式、一张卡片单独占画面时，用强调档字号（36–52），不要一行小字留下大片空白；电路图占满代码面板下方的右半边，不挤在角落。参照成片的原理段与代码段都把中部推导区用满。
- 画面只放讲解内容，不放出处、制作说明和免责说明：「精确算术」「固定版本 RTL 仿真」「示意轴非全程等比例」「显示约数」「没有给出未经综合测量的数字」、文档名与章节号、编译开关。出处只在 `outline.md` 的数字清单与 `evidence/`；约数用 ≈ 表示，示意图不加说明。`vt check` 对这类用语报错。反例（fp32-format 首稿）：几乎每页右下角都有一行 17 像素的出处小字。

## 五、动画节奏

- 画面进度全部由 beat 驱动：`p(beat, 延迟, 时长)` 返回 0 到 1。同一个 beat 里多个元素依次出现时，延迟错开 6–14 帧。
- 一个 beat 里的变化要在旁白说到它时发生：旁白前半句提到的元素，延迟不超过 30 帧。
- 转场：前一段元素 12–16 帧淡出，后一段元素晚 6–10 帧开始出现。

## 六、抽帧自查清单

`vt stills <id> 0.5 --all` 对有旁白的 beat 取语音刚结束的那一帧（字幕仍在画面上、这句话描述的画面已经到位），无旁白的 beat 取最后一帧。之后逐张检查：

- [ ] 安全区：没有元素越过左右 96 像素的边距，没有元素进入字幕区。
- [ ] 遮挡：文字与线条、圆标、箭头没有互相压住。
- [ ] 断行：画面文字没有在词中间断开；字幕的换行位置读起来自然（宽度与行数已由 `vt lint` 检查）。
- [ ] 颜色：角色色只用在对应的概念上。
- [ ] 推进：相邻两个 beat 的结束帧能看出变化，而且只变了一处。
- [ ] 静音可懂：只看这张图，能说出这一步讲了什么。
- [ ] 出处：图上每个数字都在 `outline.md` 的数字清单里，能找到出处。
- [ ] 通用：画面上没有素材项目的文件名、源文件行号或项目专有的说明。
- [ ] 只有内容：画面上没有出处、制作说明、免责说明，没有观众没学过的制作用语（RTL、实现）。
- [ ] 疏密：当前讲的东西是画面上最大的元素；没有只剩一行小字、四周大片空白的帧，也没有挤在角落、要放大才看得清的电路。
- [ ] 字形：指数、下标与正文字形一致，没有回退字体造成的忽大忽小。
