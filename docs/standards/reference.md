## 语言范例

现行讲述平实、专业、有叙述者在场。先提出需要解决的实际问题，再用具体操作和因果把概念推出来；英文术语在概念命名时出现，字幕按语音逐行展示。

| beat | 验收通过稿的原句 | 可复用的写法 |
|---|---|---|
| p26 | 现在我们可以算了：一拍最短要多长？上升沿来了，前一排先花掉时钟到输出延迟，才放出新值。 | 问题承接前面已讲过的部件，随后按时间顺序描述发生的动作 |
| p38 | 切开后，周期只需要装下最慢的那一级。所以我们切的位置有讲究：各级的延迟要差不多长。 | 先给决定关系，再从这个关系说明设计选择的原因 |
| p61 | 先看一组数：送进来之后，要过两个上升沿，结果才出现在出口。这段等待叫延迟，这里是两拍。 | 先让观众看见过程，再给名称和当前例子的量值 |
| c11 | 这八行在同一个时钟块里，同一个上升沿一起存下，合起来就是两级之间的那一排寄存器。 | 从代码共同描述的动作，收束到原理段已有的结构 |

各句要连起来读：一句产生下一句需要回答的问题，结论带着理由。画面承担形象表达，旁白准确说出谁做了什么、何时发生、产生什么结果。写法条文见 [narration.md](narration.md)，定义与概念顺序见 [principle.md](principle.md)。

## 美术与过程范例

暖底、手绘线条、文楷正文和等宽代码构成整集的基础。第 6 集把寄存器与时钟、数据与组合逻辑、有效信号分别赋予角色色，贯穿公式、波形、电路与代码。顶部保留核心公式，小节标签说明当前问题，上方说明与中部主体分层，底部字幕独占一行。

| beat | 文件 | 参照的过程与构图 |
|---|---|---|
| p01–p03 | `Opening.tsx` | 需求、已有电路与一拍过短的问题依次出现，前三句完成开场 |
| p16–p25 | `Store.tsx`、`Speed.tsx` | 电路与时序图按讲述分别出现；波形让上升沿、存数、建立与保持时间成为看得见的过程 |
| p26–p29 | `Speed.tsx` | 三段延迟逐项累加，最终回到顶部的周期下限公式 |
| p36–p43 | `Pipe.tsx` | 原有长链插入寄存器，切口与各级延迟接着变化，从图上解释级数、频率与开销 |
| p45–p49 | `Pipe.tsx` | 文献卡与原文数据一起呈现，用公开例子解释设计自由度 |
| p52–p59 | `Modules.tsx` | 模块边界、跨界路径与输出寄存器依次展开，端口与导线从部件坐标计算 |
| p61–p69 | `Flow.tsx` | 四组数按拍列推进；表格、延迟标注、数值图例与启动间隔公式分区排列 |
| p70–p73 | `Flow.tsx` | 数据与有效信号对齐流动，输入停止后，零也随流水线传到输出 |
| c01–c07、c12–c15 | `Code.tsx` | 时钟块和有效信号逐项对到寄存器，代码、说明、电路有各自空间 |
| c08–c11 | `Code.tsx` | 宽行按原文容纳；组合逻辑与中间寄存器分段出现，最后合成完整结构 |

整体对齐以完整主体为单位：时序图包含名字列与波形，电路包含部件与信号标注，表格包含行名与拍列。临时文字和图形随所属场景退场，下一步的主体有足够空间展开。规则与组件入口见 [visual.md](visual.md) 和 [code.md](code.md)。
