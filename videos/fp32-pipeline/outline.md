# fp32-pipeline 大纲：寄存器与流水线

## 观众起点与问题

- 系列与位置：`curriculum/01-fp32-mul.md` 第 6 集，前置集 fp32-format 至 fp32-boundary，也是系列第一部分（沿一次乘法）的最后一集。
- 起点：高中数学与进制转换；前置集讲过的概念：乘加、推理、拍（第 1 集），硬件描述语言与连线（第 1 集代码课），三路相乘与阶码和（第 2 集），规格化（第 3 集，组合块 `always @(*)` 与 `reg`），舍入（第 4 集），尾数进位、上溢、下溢（第 5 集，`? :` 二选一、表达式里的 `<=` 比较）。
- 情景里的需求：推理芯片里的乘法器跟着同一个时钟工作，每一拍都要收下一组新数、交出一个结果。
- 这一集要回答的问题：一次乘法是一长串组合逻辑，怎样跟上时钟，每一拍都交出一个结果。
- 开场三句：p01 推理芯片塞满乘法器，跟着同一个时钟，每拍收一组新数、交一个结果（情景）→ p02 前五集讲的一次乘法全是连线和门，数一送进来就一路算到出口（承接前五集）→ p03 这条路很长、一拍很短，一次乘法怎样每拍都交出结果（问题）。
- 前五集的代码大多是连线和组合逻辑，这一集第一次讲存数的电路，从组合逻辑一步步讲到时序逻辑；级数按设计取舍讲，先讲通用规律，再用公开文献讲业界怎么定级数，两级只用来演示，不出现任何具体项目的频率目标或综合数据。

## 小节与核心公式

六部分加开场，k01–k06 是约 1.6 秒的无旁白部件卡。小节第一句带 `section`，前一句 `hold` ≥ 0.8 秒或由部件卡隔开。

| 部分 | 小节 | 第一句怎样接过来 |
|---|---|---|
| 开场 | 每拍交一个结果（p01） | 推理芯片塞满乘法器，每拍都要交结果 |
| 01 存数 | 组合逻辑（p04） | 前五集的电路有一个共同点 |
| 01 | 组合逻辑延迟（p06） | 输出跟着变，也要花时间 |
| 01 | 时钟（p09） | 部件那么多，要有统一的节拍 |
| 01 | 时钟频率（p12） | 有了周期，一秒有几个周期 |
| 01 | 寄存器（p16） | 有了节拍，还要能存住数的部件 |
| 01 | 时序逻辑（p19） | 把组合逻辑和寄存器接起来 |
| 02 时钟能多快 | 建立时间与保持时间（p22） | 寄存器看一眼输入也要时间 |
| 02 | 时钟到输出延迟（p25） | 寄存器自己也有延迟 |
| 02 | 周期的下限（p26） | 三段延迟合起来算一拍的下限 |
| 02 | 保持时间（p31） | 保持时间查另一头 |
| 02 | 关键路径（p33） | 很多条路里最长的那条 |
| 03 流水线 | 流水级（p36） | 关键路径太长，怎么缩短 |
| 03 | 切口的位置（p38） | 切开以后周期由谁定 |
| 03 | 级数与频率（p41） | 切几级，频率与拍数各怎样变 |
| 03 | 级数是设计自由度（p44） | 标准不管几拍，级数谁来定 |
| 03 | 业界的做法（p47） | 先定频率再定级数 |
| 03 | 演示用的两级（p50） | 拿最简单的两级来演示 |
| 04 输出也存一拍 | 模块（p52） | 乘法器的结果要交给别的电路 |
| 04 | 跨过边界的路（p54） | 出口直接接组合逻辑会怎样 |
| 04 | 输出寄存器（p56） | 在出口放一排寄存器 |
| 05 每拍一个结果 | 延迟（p61） | 切了两级，单看一组数要几拍 |
| 05 | 吞吐（p62） | 两级同时在干活 |
| 05 | 启动间隔（p66） | 每拍都能送新数，叫启动间隔为一 |
| 05 | 有效信号（p70） | 每拍都有值，哪拍是真的 |
| 06 写成代码 | 时钟块（c01） | 存数的部分用新的块来写 |
| 06 | 第一级的有效信号（c06） | 有效信号的寄存器 |
| 06 | 两级之间的寄存器（c08） | 第一级算出的值存进中间一排 |
| 06 | 输出寄存器（c12） | 出口这一排 |
| 06 | 输出的有效信号（c14） | 有效信号再存一拍 |

核心公式条常驻顶部：`时钟周期 ≥ 时钟到输出延迟 + 组合逻辑延迟 + 建立时间`。时钟周期、时钟到输出延迟、建立时间用陶土（寄存器与时钟），组合逻辑延迟用蓝（组合逻辑）。开场整条降到 45%；讲到哪一项，那一项亮起并加下划线：组合逻辑延迟 p06 起、时钟周期 p11 起、建立时间 p22 起、时钟到输出延迟 p25 起，p29 整条亮起；流水线一部分讲组合逻辑延迟被切短（p36–p43），代码段整条保持亮态不加下划线。

## 类比

无贯穿式类比。「切一刀」只在开场与部件卡里出现，旁白用正式说法（插入一排寄存器、流水级）。口语比喻只做记忆的辅助，且都放在概念正式定义之后：时钟「喊口号」、寄存器「有记性」、时钟到输出延迟「磨蹭」、关键路径「拖后腿」、有效信号是「小跟班」、出口「交货」；比喻不承载论断、不引入新术语，写法见 `narration.md` 第八节。

## 代码范围

- 素材 anchorfp 固定提交，`fp/rtl/fp32_mul_pipe.v`，五段，由 `vt code` 逐字抽取：
  - `valid1` 第 34–37 行：第一级的有效信号寄存器，完整的时钟块形状。
  - `stage1` 第 65–67 行：第一级的组合逻辑（尾数相乘、阶码相加），第 2 集讲过，只高亮。
  - `regs` 第 80–87 行：第一级在上升沿存下的八个值。
  - `outreg` 第 157–160 行：出口的寄存器与最后的选择。
  - `valid2` 第 111–114 行：输出的有效信号。
- 不讲模块声明、端口与例化（第 165–195 行），也不出现模块名。
- 桥：原理段最后落在「每一级之间一排寄存器、出口一排输出寄存器、有效信号跟着数据走」，代码段按这个顺序对代码：先认时钟块与存数的 `<=`，再看第一级的有效位、两级之间的寄存器、输出寄存器、输出的有效位。
- 代码词（terms.json）：完整翻译 `always @(posedge clk)`、`posedge`、时钟块里的 `<=`（同形记号，对照第 5 集表达式里的 `<=`）、`!`、`||`、`~`、`1'b0`；信号名 `rst_n`、`flush`、`in_valid`、`v_s1`、`out_valid`、`p`、`sign_r`、`spec_sel_r` 在电路的导线上标出。`*`、`$signed`、`? :` 前几集讲过，只高亮。`reg` 回顾第 3 集：写在组合块里是组合逻辑，写在时钟块里才是寄存器。
- 代码节奏：15 个 beat 讲 23 行，0.65 beat/行。

## 角色色

寄存器与时钟用陶土；数据与组合逻辑用蓝；有效信号用绿（第 1 集符号位的绿是「一位标志」，与有效信号同类）。顶部公式条、电路、时序图、代码下划线都按这三个角色。

## 论断边界

- 「级数越多、时钟越快」指频率上限：每级组合路径变短，周期下限变小；寄存器的时钟到输出延迟与建立时间每级都要付，所以两级到不了两倍；延迟拍数同时变多，旁白两面都讲。
- 「标准不管几个拍算完」指浮点标准只定义数值与舍入，不定实现时序；流水级数是设计自由度。
- FloPoCo 的三行数据来自同一个运算电路（三个数的平方和，自定义格式）在同一种 FPGA 上按不同目标频率生成，旁白只说「同一个电路」，不说成 FP32 乘法；「做出来的电路都达到了目标」指表中的结果频率不低于目标频率。
- PG060 的 12 拍、400 MHz、70 MHz、6 拍是手册里的举例（「For instance」），旁白说「它的手册举例」；「资源大约少一半」照原文 approximately halves。
- GRFPU 的 3 拍是该设计的公称值，旁白说「有一款」，不外推成所有处理器。
- 建立时间、保持时间、时钟到输出延迟只讲概念与作用，不报具体皮秒数（随工艺与器件而变）；时序图与数轴上的长短是示意。
- 保持时间检查与周期无关，指同一个时钟、同一个上升沿发出与接收的普通路径；不展开时钟偏斜。
- 「输入在窗里变，存下的值不可靠」只讲结论，不展开亚稳态。
- 延迟 2 拍指结果相对输入晚两个上升沿出现在出口（仿真的时钟口径）；「每拍出一个结果」以流水充满为前提，旁白说「从第三拍起」。
- 「输入那头接的是上游模块存过的输出」是情景里按输出寄存器准则的设计，旁白只讲为什么输入不再存一排，不说成某个项目的做法。
- 启动间隔大于一只讲概念与厂商参数，不展开具体的复用电路。
- 本集是系列第一部分的收尾：结尾只总结一次乘法的全程，不预告加法等以后的部分。
